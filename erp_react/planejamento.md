# 🚀 Planejamento Estratégico & Arquitetura - Sistema ERP_ABP SaaS Ecosystem

Este documento contém o planejamento detalhado, histórico de desenvolvimento, motivações técnicas e o roadmap futuro da transformação do **ERP_ABP** em um **Sistema SaaS (Software as a Service) Multi-Tenant de Grande Porte**.

---

## 🎯 1. Visão Geral e Objetivo Arquitetural

A proposta central do **ERP_ABP SaaS Ecosystem** é unificar as melhores funcionalidades das plataformas mais relevantes do mercado moderno em uma única solução acessível e intuitiva para micro, pequenas e médias empresas:

*   **WhatsApp CRM & Atendimento com IA (estilo WhatsApp Web):** Centralização das conversas de todas as entidades cadastradas na conta do usuário (Clientes, Fornecedores, Colaboradores), com automações n8n e links diretos para o WhatsApp.
*   **Vitrine Virtual Compartilhada (estilo MercadoLivre / OLX / iFood):** Exibição pública dos produtos e serviços cadastrados por todos os parceiros do ecossistema em um marketplace unificado.
*   **Controle Financeiro, Estoque & PDV Completo:** Frente de caixa ultra-rápida, sangrias, controle de entradas/saídas, parcelamento de contas e relatórios em tempo real.
*   **Criptomoeda Própria (ABP Coin):** Sistema de fidelização, cashback e pagamentos P2P integrados no ecossistema.
*   **Isolamento Multi-Tenant Garantido:** Cada empresa possui seu próprio ambiente isolado via `store_id` e `user_id` no Supabase e no banco de dados local IndexedDB.

## 🛠️ 2. O Que Já Foi Criado (Histórico & Recursos Implementados)

### 🔑 2.1. Tela de Login e Autenticação SaaS (`SaaSLoginScreen.tsx` & `App.tsx`)
*   **Página Inicial de Acesso OBRIGATÓRIA:** Todo o ecossistema agora se inicia na tela de Login para garantir que nenhum usuário não autenticado acesse dados privados do ERP.
*   **Campos de Autenticação Requisitados:**
    *   Campo **E-mail do Usuário**.
    *   Campo **Senha do Usuário** equipado com o botão de alternância (ícone de olho `Eye` / `EyeOff`) para visualização segura da senha.
    *   Botão primário **"Fazer Login no Sistema"**.
    *   Botão secundário **"Entrar com a Conta do Google"** (integração OAuth Supabase + fallback para ambiente de preview).
*   **Cadastro de Novo Tenant (Empresa):** Permite o registro instantâneo de novas empresas no ecossistema, definindo Nome da Loja, Nome do Proprietário, Perfil de Acesso e Credenciais.

### 🛡️ 2.2. Isolamento de Dados Multi-Tenant (`AppContext.tsx` & Supabase)
*   **Segurança de Acesso:** Adicionado o campo `user_id` e `store_id` nas consultas de vendas, entidades, finanças e estoque no Supabase.
*   **Nenhum usuário pode acessar informações de outro:** Os dados são filtrados no client-side e protegidos por Row Level Security (RLS) no banco PostgreSQL do Supabase.

### 💬 2.3. Módulo WhatsApp CRM Integrado (`CustomerChatView.tsx`)
*   **Transformação do Chat em um WhatsApp Completo:**
    *   **Sincronização Automática com Entidades:** Todas as entidades cadastradas na conta do usuário (Clientes, Fornecedores, Colaboradores) são importadas automaticamente para a lista de contatos do chat.
    *   **Link Direto com WhatsApp Web (`wa.me`):** Botão direto para abrir o aplicativo do WhatsApp Web ou celular com mensagem pré-preenchida.
    *   **Automação n8n IA:** Suporte a webhooks de Inteligência Artificial para auto-resposta ao cliente.
    *   **Envio de Anexos de Produtos:** Envio de fichas de produtos da loja direto na conversa do chat.

### 🛒 2.4. Loja Virtual & Marketplace Unificado (`EcommerceView.tsx`)
*   **Vitrine Global do Ecossistema:** Exibição dos produtos e serviços de **todos os usuários/lojas do ecossistema** na vitrine compartilhada.
*   **Identificação do Vendedor:** Cada produto indica claramente qual empresa é responsável pelo item.
*   **Checkout & Mercado Pago:** Suporte a pagamentos via PIX, Cartão de Crédito e Boleto com simulador do Mercado Pago.

### 📊 2.5. Módulos ERP Tradicionais (PDV, Estoque, Financeiro, Entregas, Relatórios)
*   **PDV (Frente de Caixa):** Registro de vendas com código de barras, parcelamento e sangria.
*   **Financeiro:** Controle de Contas a Pagar/Receber e geração de boletos.
*   **Gestão de Entregas:** Rastreamento de motoboys e status de entrega no estilo iFood.
*   **Modo Offline-First:** Funcionamento completo sem internet via IndexedDB, sincronizando automaticamente quando a conexão é restabelecida.

## 📋 3. Estrutura do Banco de Dados PostgreSQL (Supabase SQL)

Para garantir o perfeito funcionamento do ecossistema, execute o seguinte script no SQL Editor do seu Supabase:

```sql
-- 1. Tabela de Entidades (Clientes, Fornecedores e Colaboradores)
CREATE TABLE IF NOT EXISTS entidades (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) DEFAULT auth.uid(),
  store_id TEXT DEFAULT 'tenant_default',
  nome_completo TEXT NOT NULL,
  cpf TEXT,
  data_nascimento DATE,
  email TEXT,
  telefone TEXT,
  tipo_entidade TEXT DEFAULT 'cliente',
  status_entidade TEXT DEFAULT 'ativo',
  tipo_acesso TEXT DEFAULT 'cliente',
  avatar_url TEXT,
  cep TEXT,
  logradouro TEXT,
  numero TEXT,
  bairro TEXT,
  cidade TEXT,
  estado TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Habilitar RLS em Entidades
ALTER TABLE entidades ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Permitir Leitura e Escrita do Proprietário em Entidades" 
ON entidades FOR ALL 
USING (auth.uid() = user_id OR user_id IS NULL);

-- 2. Tabela de Produtos (Estoque & Vitrine SaaS)
CREATE TABLE IF NOT EXISTS produtos (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) DEFAULT auth.uid(),
  store_id TEXT DEFAULT 'tenant_default',
  nome TEXT NOT NULL,
  codigo_barras TEXT,
  categoria TEXT DEFAULT 'Geral',
  unidade TEXT DEFAULT 'UN',
  preco_custo NUMERIC(10,2) DEFAULT 0,
  preco_venda NUMERIC(10,2) DEFAULT 0,
  quantidade_estoque NUMERIC(10,2) DEFAULT 0,
  estoque_minimo NUMERIC(10,2) DEFAULT 0,
  descricao TEXT,
  foto_url TEXT,
  ativo BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Habilitar RLS em Produtos (Leitura Pública para a Vitrine Compartilhada, Escrita do Dono)
ALTER TABLE produtos ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Permitir Leitura Global de Produtos para Vitrine" 
ON produtos FOR SELECT USING (true);

CREATE POLICY "Permitir Edição pelo Proprietário do Produto" 
ON produtos FOR ALL USING (auth.uid() = user_id OR user_id IS NULL);
```

## 🔮 4. Próximos Passos & Roadmap de Evolução

### 🚀 Fase 1: Expansão do ABP Coin & Carteira Digital (Wallet)
*   **Motivo:** Criar retenção de clientes através de cashback e pagamentos com taxas reduzidas entre lojistas do ecossistema.
*   **Como fazer:** Criar sub-módulo de Carteira na barra de navegação, exibindo saldo em ABP Coins (1 ABP Coin = R$ 1,00) e permitindo transferência via QR Code entre empresas e consumidores.

### 🏢 Fase 2: Gestão Multi-Lojas e Filiais no Mesmo Login
*   **Motivo:** Permitir que grandes clientes gerenciem múltiplas filiais de supermercado sem precisar desconectar.
*   **Como fazer:** Adicionar seletor de Filial no HeaderBar e vincular cada transação ao `store_id` da filial ativa.

### 🤖 Fase 3: Conexão Oficial WhatsApp Business Cloud API
*   **Motivo:** Habilitar disparo massivo de promoções e notificações de entrega automáticas no WhatsApp do cliente sem risco de banimento.
*   **Como fazer:** Integrar webhook da Meta Cloud API diretamente no `CustomerChatView.tsx`.

### 📄 Fase 4: Emissão Fiscal SEFAZ (NFC-e / NF-e)
*   **Motivo:** Atender exigências tributárias brasileiras para emissão de cupom fiscal no PDV.
*   **Como fazer:** Conectar API de parceiro fiscal (ex: Focus NFe, PlugNotas) ao concluir vendas no PDV.

## 🛠️ 5. Como Compilar e Hospedar no GitHub Pages / Servidor Próprio

Para compilar o projeto para hospedagem estática e gerar a pasta `dist/`:

1. Executar o comando de build no terminal:
   ```bash
   npm run build
   ```
2. A pasta `dist` será gerada no diretório raiz contendo todos os arquivos HTML, JS e CSS estáticos.
3. Copie o conteúdo de `dist/` para a branch `gh-pages` do seu repositório GitHub ou para qualquer servidor de hospedagem (Vercel, Netlify, cPanel, Apache, Nginx).
